While watch is running, the store stays open the whole time, so it may hold temporary companion files (journal-style files next to the database) for the whole session. Any other command run against the same store at the same time has to coexist with that open connection.\n\nRoute 2: on each sync, watch takes the lock, opens the store, does the work, and closes it before releasing the lock. Between syncs nothing is held open. The reasoning given is that no -wal/-shm side files are left lying around and nothing cached from an earlier sync can carry over. Other commands can use the store freely between syncs, and each sync starts from whatever is on disk right then.\n\nRoute 3: this question was not considered.
